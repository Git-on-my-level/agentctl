## Verified defect and repair

A retained child inserted before the saved index cursor between pages was absent
from a successful query. Deleting or rewriting an already visited index record
could also leave a torn membership result. Returning `complete: true` for these
results was incorrect under the retained-attributed-records coverage contract.

Every index page now reads a bounded membership proof in the same read-only
transaction as its entries. The first page captures the proof; every subsequent
page, including the final empty page, must match. A mismatch returns the existing
`ErrChildrenBounded` with no partial results. The unchanged CLI error mapping
emits exit 9, `children_query_incomplete`, `complete: false`, `retryable: true`.

The proof consists of:

- A per-parent/provider-session stamp, written atomically with admission or index
  mutation. Transaction IDs prevent stamp reuse. Current outcome/acknowledgement
  writes and admissions in unrelated scopes leave this stamp unchanged.
- A mixed-version writer fence. All current production journal transactions use
  `Journal.update`, which certifies the last committed transaction ID and retains
  the latest uncertified predecessor. An older writer cannot update the new
  scope stamps; a certificate gap therefore invalidates the proof. A subsequent
  current write preserves the gap instead of concealing the older mutation.
- An empty-scope pruning fence. Current cleanup removes stamps when the last
  index entry disappears, advancing this fence so an absent stamp cannot suffer
  an ABA through insertion/removal. Scope metadata is not retained forever just
  to maintain query generations.

These are constant-count point lookups per page, not an extra journal scan.
The query still closes read-only handles between pages of 128 entries / 256 KiB,
uses the existing 50 ms lock allowance and 1.5 s total processing budget, and
performs no write, migration, maintenance, notification or network operation.
The existing entry/byte/result/subscription/sidecar bounds are unchanged.
Attribution, exact waiter handling, attention visibility, replay, uncertain
remote admission and graph retention are unchanged.

## Mixed-version compatibility and limits

The optional bucket and metadata keys are additive under schema 1 / compatibility
epoch 1. Existing indexes do not need a backfill. A stable query succeeds without
any of the optional metadata. Its first later certified transaction anchors the
legacy fence to the previously observed transaction, so that transaction alone
need not invalidate membership.

An uncertified older transaction conservatively invalidates an in-progress
query even when it changes only outcome state. Empty-scope stamp reclamation
also conservatively invalidates unrelated in-progress queries. These cases
require retry; they never silently report an empty result. Current outcome writes
and unrelated admissions are explicit successful controls in the regressions.

An older cleanup binary can leave an unused optional scope stamp until that
scope is next mutated by current code; this is small metadata residue, not a
retained execution or a weakened deletion guard. Older query binaries do not gain
the new check retroactively. Binaries predating attribution cannot index their
launches and remain outside the documented coverage boundary.

Membership is stable from the first index page through the final checked page;
projections, acknowledgements, subscriptions and exact waiter evidence retain
their existing observation semantics. A launch after that final observation is
outside it. The accepted lost-SSH-receipt coverage limit, historical attribution
limit, uncertain remote state and inherited graph-retention policy remain.
There is no new remote lifecycle authority or claim of remote non-launch.
